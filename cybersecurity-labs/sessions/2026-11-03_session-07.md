## 2. Decoding a ufw Block Entry

| Field | Meaning |
|---|---|
| `[UFW BLOCK]` | ufw dropped this packet |
| `IN=wlan0` / `OUT=` | Arrived on Wi-Fi / not being sent out (incoming) |
| `MAC=` | Destination MAC + source MAC + `08:00` (IPv4) |
| `SRC` / `DST` | Sender / destination IP |
| `TTL=255` | Came from the local network |
| `PROTO` | TCP / UDP / other (IGMP lines have no ports) |
| `SPT` / `DPT` | Source / **destination** port |
| `SYN` | A new-connection request (step 1 of the TCP handshake) |
| `CWR ECE` | Congestion flags. Apple devices set these on SYN (a small fingerprint) |

## 6. Key Lessons

- **Correlate across sources:** log entry ↔ Lab 1 inventory ↔ `ipconfig`.
- **Separate signal from noise:** filter (grep), then summarize (`sort | uniq -c`).
- **"Filtered" only means no reply.** The block can happen on the target, the network, **or the scanner** (iOS permission).
- **Missing evidence is a finding.** Explain it before dismissing it.
- **Perfectly regular timing (125 s) means automation.**
- **Check every config layer** (`systemd-analyze cat-config`). The real setting was in a drop-in.
- **Volatile logs can be wiped by any restart.** Export evidence before shutdown.
- **A Pi without an RTC writes wrong early-boot timestamps.** Don't trust them.
