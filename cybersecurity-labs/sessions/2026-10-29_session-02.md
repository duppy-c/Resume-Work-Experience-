## 3. Display Fixes

**Clock (LXQt World Clock):** right-click the clock → Configure → Time format → 12-hour, or use the custom format `h:mm AP`.

**Screen fit:** the TV crops the edges (overscan). With the KMS driver (`vc4-kms-v3d`), `disable_overscan=1` in config.txt is ignored. The options are:
1. On the TV, set the picture size to **Dot by Dot / Full Pixel / Just Scan**.
2. Use the 1360x768 mode, since TVs usually don't zoom PC resolutions. Test with `xrandr`, then make it permanent with an autostart file. See [the command reference](../commands.md).

**Open issue:** `lxqt-config-monitor` closes right after opening. Next time, run it from the terminal and capture the error output.

**Notable policies:**

| Policy | Value | Meaning |
|---|---|---|
| DNSOverHTTPS → Enabled | false (not locked) | Parrot ships encrypted DNS **off**. The user can override it |
| NetworkPrediction | false | No DNS prefetching. Every captured name came from a page that actually loaded |
| CaptivePortal | false | No captive-portal "phone home" lookups |
| DisableAppUpdate | true | Firefox updates only through apt, so run `apt full-upgrade` regularly |
| DisableTelemetry / Studies / FeedbackCommands | true | No usage data sent to Mozilla |
| Cookies → AcceptThirdParty | never | Third-party cookies are blocked |
| EnableTrackingProtection (incl. Cryptomining, Fingerprinting) | true | Known trackers are blocked |
| SearchSuggestEnabled | false | Keystrokes are not sent to the search engine |
| SearchEngines → Default | DuckDuckGo | A privacy-focused default |

## 5. Lab 2 Results: DNS Privacy

**Question:** what can an internet provider (or anyone on the network) see when I browse?

**Method:** capture DNS on port 53 with tcpdump, browse, and count the unique names. Then enable Firefox DNS over HTTPS, clear the cache, repeat, and run a positive control.

| Test | Plain-text names leaked |
|---|---|
| Before (DoH off) | **27** |
| After (DoH Mode 3) | **0 from Firefox** |
| Positive control (`getent hosts example.org`) | 1, captured ✅ |

**Leaked names by category (before):**

| Category | Examples |
|---|---|
| Sites used | claude.ai, tryhackme.com, account.hackthebox.com |
| Google | accounts.google.com, www.google.com (Sign in with Google) |
| Chat / support | intercom.io, canny.io |
| Marketing / sales | js.hsforms.net (HubSpot), tryhackme.chilipiper.com |
| Analytics / testing | cdn.growthbook.io |
| Fonts / code CDNs | fonts.googleapis.com, kit.fontawesome.com, unpkg.com, use.typekit.net |

**Report answers:**
1. **Before and after:** 27 → 0 for Firefox.
2. **What still leaked:** `example.org`, from a non-browser program. **Firefox's DoH protects Firefox only.** apt, terminal tools and Hermes still use plain DNS. That is the reason for Future Lab 3.
3. **What remains visible:** the **destination IP addresses**, and often the **site name in the TLS handshake (SNI)** unless Encrypted Client Hello (ECH) is supported. A VPN or Tor (Parrot's AnonSurf) hides those, but the VPN provider then sees that traffic instead.

**Conclusion:** encrypted DNS is one layer of privacy, not complete privacy (defense in depth).

## 6. Key Lessons

- **One page visit leaks many third-party names** (trackers, CDNs, chat widgets).
- **A silent listener is only proof if a positive control shows it can catch something.**
- **Control your variables:** clear caches between before and after tests, or the results show false improvement.
- **"Managed by your organization":** don't panic and don't ignore it. Read the policy, attribute it (`dpkg -S`), then judge it.
- **Bracketed paste glitch:** `^[[200~` added to the start of a pasted command is harmless. Retype the command.
