## 3. Files and Settings Changed

**`/etc/systemd/resolved.conf.d/dns-over-tls.conf`**

```ini
[Resolve]
DNS=1.1.1.1#cloudflare-dns.com 1.0.0.1#cloudflare-dns.com
DNSOverTLS=yes
Domains=~.
```

| Line | Meaning |
|---|---|
| `DNS=1.1.1.1#cloudflare-dns.com` | The server address. After `#` is the name the TLS certificate must match, which blocks imposter servers |
| `DNSOverTLS=yes` | Strict mode: encrypt or fail. Never fall back to plain text |
| `Domains=~.` | Route **all** names to these servers |

**NetworkManager (connection "NoService"):** `ipv4.ignore-auto-dns yes`, `ipv6.ignore-auto-dns yes`. The router still provides the IP address, but no longer provides DNS.

**Services:** `systemd-resolved` installed and enabled. `/etc/resolv.conf` is now a link to the stub (127.0.0.53).

## 5. Rollback (if ever needed)

```bash
sudo rm /etc/systemd/resolved.conf.d/dns-over-tls.conf
sudo systemctl restart systemd-resolved
sudo nmcli connection modify NoService ipv4.ignore-auto-dns no ipv6.ignore-auto-dns no
sudo nmcli connection up NoService
```

To remove resolved completely: `sudo systemctl disable --now systemd-resolved`, then restore `~/resolv.conf.backup` to `/etc/resolv.conf`.

## 6. Key Lessons

- **Baseline first, back up first.**
- **Change one thing at a time:** install → verify → encrypt → verify.
- **Installing a package does not guarantee the service started.** Check with `systemctl status`.
- **Restart order matters:** NetworkManager must restart *after* resolved is running.
- **Close second paths** (router DNS on wlan0) instead of trusting they won't be used. This is reducing attack surface.
- **Cached answers prove nothing.** Flush before testing.
- **Positive controls** turn "silence" into evidence.
- **Verify persistence** with a reboot plus `uptime -s`.
- Non-browser traffic (apt) leaked the **OS and hardware** (Parrot, Raspberry Pi). This is passive fingerprinting.
